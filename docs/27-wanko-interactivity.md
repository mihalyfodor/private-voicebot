# 27 — Wanko interactivity: motions, cues and reactions

## Overview
Wanko ships 12 motion clips; the app uses 5 and never touches 8 of the rig's parameters (bowl lid, steam, sparkle,
blush, squint, mouth form, paws, bowl slide). This PRD wires the orphaned clips into named groups, adds click/pet
reactions, state cues (listening / thinking / tool running / greeting / shutdown), and layered expressions from the
dormant parameters — no new art. Catalogue: `docs/prototypes/wanko-motions.md` (from the 2026-08-29 research).

## User stories
- As a user, clicking Wanko gets a reaction; spam-clicking gets smaller ones, a pause gets a big one.
- As a user, I can see when Wanko is listening (small nod, ears up), thinking (head turn, lid + steam), running a tool
  (sparkle), greeting me (gasp + paws up) and settling down at shutdown (slow breathing idle).
- As a user, replies tagged happy/surprised/etc. look more alive (blush/sparkle/smile layered on the motion).
- As the developer, motions are referenced by group name from one table; no per-clip code paths.

## Technical approach
- **Groups:** the model folder is gitignored, so the app serves its own `static/models/wanko/Wanko.app.model3.json`,
  generated by `scripts/fetch_assets.sh` from the upstream file + a groups table in the script:
  `Idle: idle_01..04` (random pick), `Pet: touch_01, 02, 06` (big), `PetSmall: touch_05, 04`, `Greet: shake_02`,
  `No: shake_01`, `Thinking: touch_03`, `Listening: touch_04`. app.js loads the `.app.` file when present.
- **Click:** PIXI hit test on the `Body` hit area → `Pet` on first tap or after 4 s, `PetSmall` for taps within 4 s;
  plus a happy blend for 800 ms. Clicks never interrupt a speaking motion (queue after).
- **Cues** (driven by existing `state`/`listening` transitions in app.js): listening → `Listening` once + ears up
  blend while `hearing`; thinking → `Thinking` + `BOWL_LID` 0→30 and `YUGE_01/02` pulsing blend until first token;
  tool call (`state` shows filler) → `EFFECT` 1 blend; greeting → `Greet` after the first `speech` of the session;
  shutdown → force `idle_04` and lid closing blend before the page fades.
- **Expressions:** extend the `expressions` table: `happy` adds `EFFECT 0.6`; new `proud` (`MOUTH_FORM 1, EFFECT 1,
  ANGLE_Y 6`), `sleepy` (`EYE_* 0.35, BOWL_LID 40`), `shy` (`TERE 1, FACE_01 0.5`); the emotion tag list in the
  character card / llm.py grows by these three.
- **Idle:** random pick with no immediate repeat; `idle_04` weighted lower (long, calm).
- All in `static/app.js` avatar block + one table `MOTIONS`; server only learns the three new emotion tags.

### Decisions
- Generated `.app.model3.json` over editing the upstream file: fetch stays reproducible, groups live in the repo.
- Blends for props, clips for gestures: props are never keyed in the clips, so layering is conflict-free.
- Cues on top of existing state transitions, no new WS messages.

## Test scenarios
1. `fetch_assets.sh` produces the `.app.model3.json` with the seven groups referencing files that exist (bash test).
2. `MOTIONS` table: every group name used by app.js exists in the generated file (node test reading both).
3. Expression table: new emotions parse; llm emotion-tag whitelist includes them (unit).
4. Fixture render (node DOM stub): click → `Pet`; second click within 4 s → `PetSmall`; state `thinking` sets lid/steam
   targets; state `speaking` clears them; greeting fires once per session.
5. Manual: tap Wanko, watch the cues through one full turn (listen → think → tool → speak), shutdown settle.

## Out of scope
New motion authoring, expression files, lip-sync visemes (parked), sounds.
