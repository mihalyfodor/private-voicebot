# 29 — Playwright end-to-end tests

## Overview
A thin browser-level test layer over the real server: `chatbot.py` is started as a subprocess against a temporary
vault, isolated settings/memory files and a free port, and headless Chromium drives `static/app.js` the way the user
does. Unit tests cover the pieces; these catch the seams (websocket wiring, DOM, dialogs, ⌘S) that the node fixture
cannot. Screenshots land in `/tmp/e2e/` for a human look.

## User stories
- As the developer, I run one command and see the app load, the Wiki editor round-trip a save, and the rename /
  delete / create-from-red-link flows change files on disk — without touching `~/llm-wiki`, `settings.json` or
  `memory.json`.
- As the developer, one optional live test types a chat message and shows the reply streamed and spoken.

## UI/UX
No UI changes. Tests observe the existing DOM: `#stage` canvas, rail items, `#wiki-*` elements, the page-head
buttons (`.wiki-edit`, `.wiki-save`, `.wiki-more`, `.wiki-menu-item`), `#status` text and `#history .msg`.

## Technical approach
- `tests/e2e/conftest.py`: session fixture `server` spawns `python chatbot.py` with `WIKI_PATH=<tmp>/wiki`,
  `SETTINGS_PATH`, `MEMORY_DIR`, `PORT=<free>`, `OPEN_BROWSER=0`; stdout/stderr go to `<tmp>/server.log`; waits for
  the port; yields `(base_url, vault)`; SIGTERM on teardown. `page` fixture: Playwright sync API, Chromium with the
  WebGL flags from `scripts/screenshot.py`, collects `pageerror` + console errors and fails the test on them.
  `shot(name)` saves `/tmp/e2e/<test>-<name>.png`.
- The vault is seeded with plain files before the server starts; the app's own `ensure_vault()` adds the layout,
  index and the initial git commit on first Wiki open.
- Marker `e2e`, excluded by default like `live`; run with `python -m pytest -m e2e tests/e2e`.
- Dialogs (`prompt`/`confirm`) are answered with `page.once("dialog", ...)`.

### Decisions
- One server per session, ordered tests over one seeded vault (each test uses its own pages) — a fresh server per
  test would cost a Kokoro load (~seconds) each.
- Env overrides for `settings.json` (`SETTINGS_PATH`) and the memory files (`MEMORY_DIR`) are added — the only app
  change; both default to the current locations.
- Plain functions, no page objects; generous but bounded timeouts (page load 30 s, actions 10 s, live reply 120 s).
- Live scenario is one turn, marked `e2e` + `live`, skipped when oMLX is not reachable.

## Data model
Temp vault: `people/anna` (tags, links to `projects/atlas` by alias and to the missing `people/bob`),
`projects/atlas` (tags, links back to anna), `notes/scratch`. Nothing persists past the run.

## Test scenarios
1. App loads: `#stage` present, `#status` reaches idle text, no page/console errors.
2. Wiki view renders `people/anna`: `<h1>`/`<h2>` headings, the alias link text "Atlas project", a red link for `bob`.
3. Edit → type → ⌘S: file on disk contains the new line, vault `git log` has exactly one new commit; a second edit
   saved via the Save button adds one more.
4. Stale etag: page open, file changed on disk, save → `#wiki-conflict` visible, disk text unchanged.
5. Red link click → confirm → `people/bob.md` exists, the link renders as known.
6. Rename via ⋯ menu → `people/anna.md` gone, `people/anna-k.md` exists, `projects/atlas.md` links rewritten.
7. Delete via ⋯ menu → file gone, one more commit.
8. Tags group: clicking `#platform` narrows the list to the tagged pages; clicking again clears.
9. Search box: typing `atlas` shows a results group with a hit for the project page.
10. Live (oMLX): type "Say hello in one short sentence." → status passes through thinking/speaking, an assistant
    `.msg` appears with non-empty text, state returns to idle.

## Out of scope
Voice/mic paths, hands-free, memory editor, sources intake, settings view, cross-browser, CI wiring, visual diffing.
